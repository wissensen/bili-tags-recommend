二期包含两个功能：
1. 登录 / 注册（前置鉴权）
2. 基本设置的「一键润色」（多模态大模型读封面+标题+简介，润色标题与简介）

## 功能一：登录 / 注册

### 目标
在投稿链路前置一个登录/注册页，登录成功后才能上传视频、分析、投稿。数据库记录账号与密码（哈希）。

### 可行性
成熟方案，且与现有结构天然衔接：当前用匿名 `owner_id`（签名 cookie）区分访客，登录后**把 `owner_id` 换成真实用户 id**，上传/分析/投稿的归属校验逻辑几乎不动。

> 注意：PRD 原将「登录/鉴权」列为非目标，二期做它属于有意扩展。

### 架构

```
未登录用户
  │ 访问任意投稿页 → 中间件拦截 → 跳转 /login
  ▼
登录 / 注册页
  │ 注册：POST /api/auth/register  → 存 users（密码哈希+盐）
  │ 登录：POST /api/auth/login     → 校验 → 下发会话 cookie
  ▼
已登录：会话 cookie 携带 userId → 后续接口用 userId 作为 owner_id
```

### 数据模型（新增迁移）

```sql
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,   -- PBKDF2 派生值（不含明文）
  password_salt TEXT NOT NULL,   -- 每用户独立随机盐
  created_at TEXT NOT NULL
);

CREATE TABLE sessions (
  id TEXT PRIMARY KEY,           -- 会话 token（随机）
  user_id TEXT NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL
);
CREATE INDEX sessions_user_idx ON sessions (user_id);
```

### 密码安全（关键）
- **绝不存明文**。用哈希 + 每用户随机盐。
- Cloudflare Workers **不能用 bcrypt 等原生库**，改用 Workers 内置 Web Crypto 的 **PBKDF2**（`crypto.subtle.deriveBits`，SHA-256，足够多的迭代次数）。
- 登录时用同样的盐和迭代重算，比对哈希，用恒定时间比较避免时序泄露。

### 接口
| 方法 | 路径 | 功能 | 入参 | 返回 |
| --- | --- | --- | --- | --- |
| POST | `/api/auth/register` | 注册 | username, password | 成功后自动登录或提示去登录 |
| POST | `/api/auth/login` | 登录 | username, password | 下发会话 cookie；返回用户信息 |
| POST | `/api/auth/logout` | 登出 | — | 清除会话 |
| GET | `/api/auth/me` | 当前用户 | — | userId / username 或 401 |

### 鉴权改造
- 现有 `getVisitor`（匿名 cookie）→ 升级为 `getUser`：读会话 cookie → 查 `sessions` → 得到 `userId`。
- 投稿相关接口把 `owner_id` 从匿名 id 换成 `userId`。逻辑同构，改动集中在 `lib/cloudflare.ts` 的身份获取处。
- 未登录访问投稿接口/页面 → 401 / 跳转登录（Next.js middleware 或页面级守卫）。

### 前端
- 新增 `/login` 页（登录 + 注册切换）。
- 投稿主页在无有效会话时重定向到 `/login`。
- 顶部显示当前用户名 + 登出。

### 边界
- 用户名唯一性（`UNIQUE` 约束 + 注册冲突提示）。
- 密码最小长度等基本校验。
- 会话过期（`expires_at`）与登出清理。
- 二期不做：找回密码、第三方登录、邮箱验证、权限分级（YAGNI）。

## 功能二：一键润色（多模态大模型路径）

### 目标
在第二步「基本设置」加一个「一键润色」按钮。AI **读取封面图**，并结合已填的标题/简介，**有则润色、无则生成**标题与简介（不改分区）。页面新增**简介**字段（选填）。
- **启用条件**：只要**封面已填写**，按钮即可点（封面是多模态读图的必备依据）。标题、简介可为空——为空时 AI 直接据封面生成。

### 路径选择（已定）
走**多模态大模型路径**：AI 真正「看」封面图片内容来润色，而非仅凭文字。

**模型选型（已定）**：通义千问 **Qwen3-VL-27B**（VL = 视觉多模态版，能读图），通过**阿里云百炼（DashScope）API** 调用。
- 百炼提供 OpenAI 兼容的调用方式，后端用标准 HTTP 即可请求，无需自部署。
- 需在阿里云百炼开通服务、拿到 API Key。

### AI 的输入
- **封面图**（必填，作为视觉输入）：以图片形式传给多模态模型，是生成/润色的核心依据。
- **已填标题**（选填）：有则润色，无则据封面生成。
- **已填简介**（选填）：有则润色，无则据封面生成。

### 架构

```
第二步「基本设置」
  │ 封面已填 → 「一键润色」按钮可点（标题/简介可空）
  │ 用户点击
  ▼
POST /api/ai/polish   （multipart 或 base64 传封面图 + title? + summary?）
  │ 后端拼 prompt，把封面图 + 现有文本发给多模态模型
  │ （API Key 存 Workers secret，仅服务端）
  │ 要求模型据封面「有则润色、无则生成」，返回结构化 JSON：{ title, summary }
  ▼
返回 { title, summary }
  │ 前端用结果填入/替换标题、简介（用户可再改）
  ▼
用户确认 / 手动微调
```

### 接口
| 方法 | 路径 | 功能 |
| --- | --- | --- |
| POST | `/api/ai/polish` | 多模态模型读封面+标题+简介，润色标题与简介 |

**入参**：封面图（`multipart/form-data` 文件，或 base64 字符串，**必填**）+ `{ title?, summary? }`（均选填）。
**返回**：`{ title: string, summary: string }`。
**校验**：缺封面 → 400；结果套用现有标题长度、简介长度上限（超长截断或让前端提示）。

### 多模态接入要点（关键）
- **百炼 API Key 只放服务端**：用 `wrangler secret` 存（如 `DASHSCOPE_API_KEY`），后端调用，**绝不进前端**。
- **调用方式**：百炼 DashScope 支持 OpenAI 兼容接口，后端向其 endpoint 发多模态 chat 请求（`messages` 里带 image 内容块 + 文本），指定模型为 Qwen3-VL-27B 对应的模型名。图片可用 base64 data URL 或可访问的图片 URL。
- **封面图如何送达**：本期视频/封面仍是 mock、未上传到对象存储，封面图只在浏览器本地。所以润色接口需前端**把封面图字节直接传给后端**（multipart 或 base64），后端再以 base64 data URL 形式转发给百炼——不依赖 OSS。标 `TODO(storage)`：接入对象存储后可改为传图片 URL。
- **图片大小限制**：封面已限 5MB（前端现有校验），base64 膨胀约 33%，注意 Workers 请求体上限；必要时压缩或走 multipart。
- **强制结构化输出**：prompt 要求只返回严格 JSON（title/summary），后端解析；失败兜底（保留原值 + 友好提示）。
- **超时与失败**：百炼调用设超时，失败/超时返回可读错误码与原因。**前端据此弹出提示，说明失败原因（如「AI 服务超时」「AI 暂不可用」），引导用户手动重试**；不自动重试，保留用户已填内容，不阻塞手动编辑。
- **成本与频率**：多模态调用较贵，按钮 loading 期间禁用重复点击；可选加每用户频率限制。

### 数据模型
- 新增**简介**字段：`submissions` 表加一列 `summary TEXT`（可空），提交接口透传落库。**简介长度上限 300 字**（前端校验 + 后端截断/校验）。
- 分区不变（本功能不改分区）。

### 前端改动
- 第二步表单新增：
  - 「简介」输入框（选填，多行）——可 AI 润色、可手填，随稿件提交。
  - 「一键润色」按钮：**封面填写后即启用**（标题/简介可空），带 loading 态。
- 点击后把封面图 + 现有标题/简介发给 `/api/ai/polish`，用返回的 title/summary 填入/替换对应控件；用户可继续改。
- 校验：标题沿用现有长度规则；简介上限 300 字（实时计数 + 超限提示）。

### 边界
- 封面未填 → 按钮禁用（唯一前置约束）。
- 标题/简介为空 → 正常，AI 据封面生成。
- AI 超时 / 服务不可用 → 弹出提示说明原因，引导用户手动重试；保留已填内容，不阻塞手动编辑。
- 简介选填：不填不影响提交。
- 二期不做：封面 AI 生成（这里是「读」封面，不是「生成」封面）、真实视频画面理解、流式输出、多轮对话。

## 建议实施顺序

1. **功能一（登录/注册）** 先做：它改的是身份底座，功能二里 AI 调用也归属到用户，先立好用户体系更顺。
2. **功能二（一键润色）** 后做：依赖多模态大模型 API 接入；封面图字节直传后端，独立于对象存储，可单独落地。

两个功能各自独立，落地时分别走一次「设计 → 实现计划 → 执行」。真实视频画面理解归为三期，依赖对象存储与视频抽帧/多模态。

## 已确认
- **登录方式**：用户名 + 密码（不做手机号/邮箱）。
- **简介长度上限**：300 字。
- **AI 调用失败/超时**：前端弹出提示，说明失败原因，引导用户手动重试（保留已填内容，不阻塞手动编辑）。
- **模型**：Qwen3-VL-27B，经阿里云百炼（DashScope）调用。

## 后续细化点（实施时定）
- 百炼上该模型的**准确模型名**与 endpoint。
- 封面图传参方式：multipart 文件 vs base64（取决于 Workers 请求体限制与实现便利）。
- 百炼调用的具体超时时长（如 30s）与是否自动重试（当前定为不自动重试，交由用户手动触发）。
